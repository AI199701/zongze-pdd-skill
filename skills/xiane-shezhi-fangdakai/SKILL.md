# 限额设置与放开节奏

## R — 原文依据

> 保本70%及以下的这种投产计划，我们要把限额卡在100到150左右……保本85%附近左右的链接，就是在微亏附近的链接，限额才可以在300块钱左右。……限额放开幅度一定是由小变大。……把花到的实际花费作为真实限额，而设置值只是控制实际花费的手段。

来源：aweme 7629338080274080966（3769 字）、7553993611747462441（3190 字）、7686491028023077267。

## I — 解读

限额是**控速阀门 + 止损器**。按"当前投产 vs 保本"分档设限额，放开幅度由小变大；真实限额是实际花费，不是设置值。

## A1 — 原案例（口播细节）

| 投产位置 | 限额 |
|---|---|
| 保本 70% 及以下 | 100–150 |
| 保本 85% 附近（微亏） | 250–300 |
| 保本及保本附近 | 400 以上 |

- 投产越亏，限额越低（同时向平台传递"我在亏损"的信号）。
- 设置值不变而实际花费变多：小幅 → 选区间内更低限额值；幅度大 → 直接压限额；幅度中等 → 不沉淀，直接提投产。
- 1000/天 一次花掉，不如 300/天 分三天花，给系统留沉淀时间。

## A2 — 迁移与区分

与「车损决策」区别：车损定"亏多少"，限额定"花多快"。与「提投产」区别：限额是刹车，提投产是油门，必须交替。

合成演练：保本 2.8、当前 2.1（保本 75%）→ 限额 100–150 → 两次提投产 → 到保本 85% 时把限额放到 250–300。

## E — 执行契约

- 输入：当前投产、保本投产、实际花费、设置值。
- 输出：限额档位 + 放开幅度 + 先提投产还是先放限额。
- 分支：实际花费超设置值 → 压限额；投产接近保本 → 限额放到 400+。
- 完成标准：限额档位与投产位置匹配，且放开幅度逐次变大。


### 失败分支（if-then）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 实际花费超设置值 | 小幅选区间内更低限额值 | 幅度大 → 直接压限额 |
| 限额下午就花完 | 视为正常，不加限额 | 连续 3 天 → 提投产 |
| 投产接近保本仍花不完 | 限额放到 400+ | 仍花不完 → 查出价是否过低 |

## B — 边界

不适用于自然流链接；保本算错则限额档位全错。

## 口播补充

- 限额放开必须"由小变大"，前期少放、临近保本再多放，防止花冒。
- 限额卡住后可能在下午 3 点就花完，这属于正常，不要因为"花得快"就加限额。

## 反模式黑名单

- 不要把设置值当真实限额
- 不要一次性大幅放开限额
- 不要在亏损时放高限额
- 不要因为花得快就加限额

## 执行检查点

- 🔴 放限额前：确认当前投产位置
- 🛑 实际花费超设置值 20%：STOP，压限额
