# 空烧 / 投产飘黄 / 被锁异常处理

## R — 原文依据

> 空烧最容易出现的原因和解决办法，出价不够就加，定价问题就测，内功问题就改，重复铺货就删，平均花费就抬。……投产飘黄不影响实际付费速率不用过多关心……投产上限被锁耐心等待解锁即可一般最多三天。

来源：aweme 7626727226923568895、7585174251209379135。

## I — 解读

异常处理要**先分类再动手**：空烧按"出价/定价/内功/铺货/花费"五因定位；投产飘黄、被锁多为系统态，不应急于操作。

## A1 — 原案例

原文空烧四步：先一次大幅加出价降投产 → 不行合理裂变重测 → 再不行调 SKU 布局缩短最低最高价倍差 → 最后重新测定价。

## A2 — 迁移与区分

与「数据指标」区别：本能力是异常处置 SOP。合成演练：空烧 → 加出价降投产 → 仍空烧 → 裂变重测 → 调 SKU → 重测定价。

## E — 执行契约

- 输入：异常类型（空烧/飘黄/被锁）、当前出价、定价、内功状态。
- 输出：按序处置步骤 + 停止条件。
- 分支：三步后仍空烧 → 判定链接该舍。
- 完成标准：异常消除或明确放弃该链接。

## B — 边界

不适用于平台级故障；被锁超过三天需人工核查。
